# ST20 Embedded Toolset R2.3.1 Executable Reference

This reference describes all nine `.exe` files present in
the ST20R2.3.1 installation's `bin` directory, inventoried on 2026-10-12.
The installation's `version` file identifies it as **R2.3.1.2**; the bundled
Delivery Manual describes the R2.3.1 release. These are Windows host programs
for developing and debugging ST20 applications, not ST20 firmware executables.
They cannot be launched directly as native macOS programs.

Descriptions use the manuals supplied with this installation. **Documented**
means the bundled documentation identifies the tool's role. **Inferred** marks
an interpretation not directly established by the cited documentation.
No executables were run to prepare this reference. The inventory describes this
installation, not every component available in every R2.3 package.

## Compiler and Binary Tools

| Executable | Description | Evidence |
| --- | --- | --- |
| `st20cc.exe` | Main compiler/linker driver. Wraps the ANSI C/C++ compiler and compacting linker, accepts source, assembly, object, and library inputs, and coordinates compilation and linking. C++ is converted to C before subsequent compilation. Produces linked units or ROM images according to the selected configuration. This is the usual command-line entry point for building an application. | Documented: User Manual, section 1.2.1, section 1.2.8, and chapter 9. |
| `st20edg.exe` | C++ front-end component, consistent with the toolset's documented C++-to-C compilation stage. Normally use the `st20cc` driver for C++ builds; a standalone invocation contract for this executable is not established here. | Inferred identification from the executable name and the C++ pipeline documented in User Manual, section 1.2.1; Delivery Manual, section 1.4. |
| `st20icc.exe` | Underlying ST20 C compiler, distinct from the `st20cc` driver. Compiles C source as part of the build pipeline; normally reached through the driver. | Documented: User Manual, Figure 1, ST20 Embedded Toolset architecture for ANSI C. |
| `st20link.exe` | Underlying linker. Combines compiled objects and libraries and produces linked application output or ROM images according to the target configuration. Normally invoked through `st20cc`; it is not the loader or debugger. | Documented: User Manual, Figure 1 and chapter 9. |
| `st20libr.exe` | Object librarian. Combines object files or existing libraries into a library that can be passed to the linker. | Documented: User Manual, section 1.2.3; Reference Manual, chapter 2. |
| `st20list.exe` | File inspection/listing tool. Displays most toolset file types, with options controlling the display format. Useful for inspecting build artifacts without loading them onto a target; it is not a simulator. | Documented: User Manual, section 1.2.5; Reference Manual, librarian and lister documentation. |

## Loading, Debugging, and Simulation

| Executable | Description | Evidence |
| --- | --- | --- |
| `st20run.exe` | Application loader, execution controller, and debugger. Loads and runs applications on supported silicon or simulator targets. On Windows, ST Visual Develop provides the graphical development/debugging interface; the User Manual describes `st20run -g` as the UNIX graphical interface. Target configuration and the appropriate host connection are required for hardware debugging. | Documented: User Manual, section 1.2.2, chapters 8 and 10, and appendix B. |
| `st20sim.exe` | ST20 instruction-set simulator. The bundled User Manual describes ST20-C1 and ST20-C2 core simulation, trace generation, and cycle-time statistics. Can be invoked directly or used as a target for `st20run`. This is ST's supplied simulator, separate from this repository's emulator; core simulation does not by itself establish a complete peripheral model for a particular SoC or board. | Documented: User Manual, section 1.2.6; Reference Manual, chapter 7. The board-model limitation distinguishes core simulation from full-system emulation. |

## Visual Development

| Executable | Description | Evidence |
| --- | --- | --- |
| `st20dev.exe` | ST Visual Develop, the Windows graphical interface to the toolset. Provides source editing and application compilation, linking, and debugging. Controls the underlying tools rather than replacing the compiler, linker, or simulator. Its environment can be set up automatically from the location of the executable. | Documented: User Manual, section 1.2.7, section 1.4.2, chapters 2-5, and appendix A; Delivery Manual, section 1.3. |

## Differences from the R1.8.1 Inventory

- This installation contains nine `.exe` files, compared with 24 in the
  [R1.8.1 reference](ST20R1.8.1-executables.md). The compiler, linker, librarian,
  lister, loader/debugger, and simulator names remain present.
- `st20dev.exe` is present; `stvmake.exe` and the older editor-server, console,
  help-server, and JPI diagnostic/driver-setup executables listed in that
  reference are not present in this installation's `bin` directory. Absence
  from this directory does not establish that equivalent functionality is
  unavailable elsewhere or integrated into another component.
- The R2.3 User Manual describes a tool named `stemi` for external-memory
  interface configuration in section 1.2.4. Neither `stemi.exe` nor
  `stvemi.exe` is present in this inventory, so neither is listed as an
  installed executable above.
- The User Manual, section 1.2.9, describes support for DCU3 as well as DCU2,
  whereas R1.8.1 and earlier supported DCU2 only. Section 1.2.10 describes
  Ethernet host connections and, on Windows, parallel-port or USB connections.
  Actual hardware compatibility still depends on the target and interface.

The directory also contains `st20dev.com`, DLLs, and a batch file. These are
outside the `.exe` inventory; no behavior is inferred for the `.com` file merely
from its shared basename with `st20dev.exe`.

## Typical Workflow

1. For command-line use on Windows, set `ST20ROOT` to the installation root and
   add its `bin` directory to `PATH`. The supplied `bin/ST20.bat` demonstrates
   this setup, but its paths are installation-specific. Retain the supplied
   startup scripts and configuration directories: the User Manual, section
   1.4, identifies these as necessary parts of the tool environment.
2. Open `st20dev.exe` for graphical editing, building, and debugging, or build
   from the command line with `st20cc.exe`. Use `st20libr.exe` to create
   libraries and `st20list.exe` to inspect artifacts.
3. Load and debug with `st20run.exe` and a configured hardware or simulator
   target. Use `st20sim.exe` directly for simulator runs when appropriate.
4. Select configuration files and host interfaces appropriate to the actual
   processor and board. Do not reuse an unrelated evaluation-board definition
   as though it were a universal firmware configuration.

For example, if the installation is actually located at
`C:\STM\ST20R2.3.1`, the command-line environment can be initialized as follows.
Substitute the real Windows-visible path before using these commands.

```bat
set ST20ROOT=C:\STM\ST20R2.3.1
set PATH=%ST20ROOT%\bin;%PATH%
st20dev.exe
```

## Sources and Scope

The primary sources are bundled with the ST20R2.3.1 installation:

- `doc/st20/ST20_User_manual.pdf`: ST20 Embedded Toolset R2.3 User Manual,
  ADCS 7143840 Rev. L; tool overview, environment, graphical development,
  compilation, loading, and debugging.
- `doc/st20/ST20_Reference_manual.pdf`: ST20 Embedded Toolset R2.3 Reference
  Manual, ADCS 7250966 Rev. I; supporting tools and simulator reference.
- `doc/st20/ST20_Delivery_Manual.pdf`: ST20 Embedded Toolset R2.3 Delivery
  Manual, toolset version R2.3.1, ADCS 7257995 Rev. K; release and installation
  context.
- `doc/docs.htm`: bundled documentation index and document revision identifiers.
- `version`: installed version identifier, R2.3.1.2.
- `bin/ST20.bat` and the `bin` directory listing: local environment setup and
  executable inventory.

These sources establish tool roles and the local inventory, not complete runtime
behavior or compatibility with arbitrary firmware. Descriptions have not been
copied from R1.8.1 on the assumption that all release behavior is unchanged.
DLLs, drivers, configuration files, `.com` files, and batch files are outside
the executable inventory requested here.
