# ST20 Embedded Toolset R1.8.1 Executable Reference

This reference describes all 24 `.exe` files present in
`/Users/apple/Documents/Dekoder/ST20R1.8.1/bin`, inventoried on 2026-10-10.
These are Windows host programs for developing and debugging ST20 applications,
not ST20 firmware executables. They cannot be launched directly as native macOS
programs.

Descriptions use the manuals and release notes supplied with this installation,
supplemented by embedded executable strings. **Documented** means the bundled
documentation identifies the tool's role. **Binary evidence** means the
identification comes from embedded names, messages, or imported APIs.
**Inferred** marks an interpretation that has not been confirmed by documentation
or execution. No executables were run to prepare this reference.

## Compiler and Binary Tools

| Executable | Description | Evidence |
| --- | --- | --- |
| `st20cc.exe` | Main compiler/linker driver. Accepts C, assembly, object, and library inputs and coordinates compilation and linking. The toolset also supports C++ through its C++ front end. Produces application images according to command-language configuration, including linked units and ROM output. This is the usual entry point for building an application, rather than invoking the internal compiler and linker separately. | Documented: User Manual, sections 1.2.1 and 1.2.6, chapters 3-5. |
| `st20edg.exe` | C++ front end used by the build toolchain. Processes C++ and lowers it to C for subsequent compilation, with template-instantiation support. | `st20icc.exe` | Underlying ST20 C compiler, distinct from the `st20cc` driver. Converts source into ST20 object code as part of the compilation pipeline; normally reached through the driver. | Documented: User Manual, toolset architecture diagram, Figure 1.1. |
| `st20link.exe` | Underlying linker. Combines object code and libraries and applies target memory placement/configuration to produce linked application output. Normally invoked by `st20cc`; it is not the program loader or debugger. | Documented: User Manual, Figure 1.1 and linking/configuration chapters; Delivery Manual references its segment-placement behavior. |
| `st20libr.exe` | Object librarian. Combines object files or existing libraries into a library for use by the linker. Supports the toolset's command-language interface. | Documented: User Manual, section 1.2.3 and chapter 11. |
| `st20list.exe` | File inspection/listing tool. Displays most toolset file types, with options controlling the listing format. Useful for inspecting toolchain artifacts without loading them onto a target; it is not a simulator. | Documented: User Manual, section 1.2.4 and chapter 12. |

## Typical Workflow

1. Configure the Windows host environment: add the installation's `bin` directory
   to `PATH` and set `ST20ROOT` to the installation root. The supplied `ST20.bat`
   demonstrates this using `C:\STM\ST20R1.8.1`.
2. Build with `st20cc.exe`, optionally through `stvmake.exe`. The driver uses the
   compiler, C++ front end when needed, and linker. Use `st20libr.exe` to create
   libraries and `st20list.exe` to inspect artifacts.
3. Load/debug with `st20run.exe`, using a configured hardware or simulator target.
   `st20sim.exe` can also be used directly.
4. For supported external-memory hardware, use `stvemi.exe` to prepare EMI
   configuration. For legacy JPI parallel-port hardware, driver installation,
   configuration, and diagnostics are separate host-side tasks.

The User Manual gives the following example commands for its supplied EVAL-5500
configuration. These require the appropriate example files and target definitions;
they are not universal commands for arbitrary firmware images.

```bat
st20cc hello.c -T st5500.cfg -p link -g
st20run -i st5500.cfg -t eval5500 hello.lku -g
st20run -i st5500.cfg -t eval5500sim hello.lku -g
```

Additional evidence comes from readable strings and imported API names in the
installed executables, and from `bin/ST20.bat`. Those observations establish
identities or capabilities, not complete runtime behavior. Unconfirmed helper
roles remain explicitly labeled above. DLLs, drivers, configuration files, and
batch files are outside the executable inventory requested here.

The other toolset PDFs in this directory include later releases; their behavior
has not been assumed to apply to these R1.8.1 binaries.
